## 0. Architecture commune
- /communaute (app/communaute/page.tsx:18-25, 126-155) monte deux composants `dynamic(ssr:false)`, préchargés à l'idle (l.40-57), montés à la 1re ouverture puis conservés. Déclencheurs : barre haute CommunityFeedTopBar (« Explorer et rechercher » → onglet `carnets` ; loupe « Rechercher dans la communauté » → `initialSearch` ; « + Créer dans l’application » → CreateDrawer `post`) ; le « + » de la barre des stories ouvre CreateDrawer en `story`. Création exige user non anonyme, sinon `requireAuth` (toast « Connectez-vous pour continuer. » / « Créez un compte pour enregistrer, commenter ou publier. » + redirection /connexion ou /inscription). Succès : `handleCreated` ferme, rafraîchit fil ou stories, toast « Création publiée. ».
- Les DEUX tiroirs reposent sur le même `CommunityDrawer` (CD) : portail `document.body`, `.lkdv-drawer-layer` (fixed inset 0, z 90, CF:624) > `.lkdv-drawer-backdrop` + `.lkdv-half-drawer[role=dialog][aria-modal]`. AUCUNE des primitives de /compte n'est utilisée : ni SlotShell, DrawerShell, LensPager (hors StepPager qui l'importe avec count=1), OverlaySheet/CompteOverlayHost, ni `components/ui/drawer/*`. Seule primitive partagée : `CapsuleTabs` (components/ui/CapsuleTabs.tsx) + `Switch`, `Icon`, `useHapticFeedback`.
- CD (CommunityDrawer.tsx) : effet à l'ouverture l.40-79 (`body.style.overflow='hidden'`, focus après 50 ms sur `[data-autofocus]` sinon 1er `button, input, a`, Échap = fermer l.49-54, piège de Tab manuel l.55-70, focus rendu au déclencheur) ; `if(!open) return null` l.81 (donc aucune animation de sortie) ; poignée `.lkdv-drawer-grab` l.98-129 (aria-hidden, Pointer Events, delta>80 px → `onClose`, sinon `setDragY(0)`), corps `.lkdv-drawer-body` l.130-143 avec swipe horizontal (|dx|≥60 px, `onSwipeLeft/Right`). Aucun en-tête, aucun titre visible, aucune croix (`title` ne sert qu'à `aria-label`).

Fermer : Échap, clic sur le voile, glisser la poignée >80 px. Pas de pile/sous-tiroir : le « détail » remplace le contenu sur place (pas de bouton retour ; swipe droite = élément précédent, ou fermeture du détail au 1er).

Pour `recherche`, CSD:349 passe `heightPercent=80` (style inline `height:80dvh`) ET la classe `lkdv-drawer--search` (CPP:296-300 `80dvh !important`), mais CF:2057 (`:not(:has(.lkdv-create-selector))`, `50dvh !important`, spécificité égale, chargée après CPP) l'emporte : les 80 % sont très probablement morts (à vérifier).
### A.2 Volet « Recherche » (CSD:370-443)
- Champ hero `.lkdv-search-box--hero` (CF:953, 48 px, radius 999, fond rgba(255,255,255,.92), icône loupe 17) ; input placeholder `Posts, carnets, clubs, sorties, membres…`, aria-label `Rechercher dans toute la communauté`, non obligatoire, `data-autofocus` seulement si ouvert via la loupe (focus clavier auto → clavier mobile s'ouvre alors). Aucun état d'erreur : `catch` → résultats vides, donc affiche « Aucun résultat » comme une vraie absence. Moins de 2 caractères : rien (pas de suggestions/récents ; `.lkdv-search-prompt` CF:1040 jamais rendu).
- Chargement : `<p class=lkdv-section-loading>Recherche…</p>` (aria-busy sur le conteneur), masque les résultats. Vide : « Aucun résultat pour « X ». » + bouton `Effacer la recherche` (CSD:404-411, 32 px de haut).

Tous appellent `onClose`. `scope` (filtre par type, CSD:139,320-323) n'a plus d'UI : toujours `all` ; CSS `.lkdv-search-scope`, `.lkdv-search-section`, `.lkdv-result-group-head`, `.lkdv-search-prompt` orphelins.

## B. Tiroir « Créer » — CreateDrawer (CR)

Sélecteur `CapsuleTabs` 6 types (CR:30-37, icônes 19 px, `ariaLabel` « Type de création », classes `lkdv-create-selector lkdv-slot-selector`) : Publication(Pencil), Carnet(BookOpen), Sortie(Map), Kit(Backpack), Club(Users), Story(Plus). - Étapes : `CREATE_STEPS` (SP:23-59) — Publication (1 seule étape active « Format », SP/Post:35), Story 3 (Média, Édition, Diffusion), Carnet(5, formulaire orphelin), Sortie 4 (Type & lieu, Itinéraire, Participants, Sécurité), Kit 3 (Inventaire, Compléter, Partager), Club 4 (Identité, Univers, Adhésion, Publication). Pager `StepPager` : une seule pane rendue, les autres dans un `div display:none inert aria-hidden` (SP:195-201) ; swipe horizontal |dx|≥50 hors input/textarea/select (SP:149-171) ; avancer exige `form.trigger(champs de l'étape)` sinon rebond 420 ms (`data-bounce`) ; flèches ←/→ gérées sur la racine SANS filtrer la cible (SP:145-148). Capsule d'étapes : `inline` (Sortie, Club, Kit) = barre statique en tête (max 320 px, 32 px) ; non-inline (Story) = portail `document.body` fixed bas-droite (right 26, bottom 12, 187×32, z 2147483000, CF:2149-2160).
- Le bouton « Continuer » est présent dans le footer mais masqué (`:has([data-step-action=continue]){display:none!important}`, CF:1900) : on avance uniquement par capsule ou swipe ; seul le footer de la dernière étape (« Publier », « Publier la story », « Créer la sortie », « Créer le kit », « Créer le club ») est visible. Bouton « Retour » (`lkdv-create-step-back`) passé à `actions` mais jamais rendu par StepPager.
- Fermeture : `requestClose` (CR:64-73) : si envoi en cours ou brouillon vide → ferme ; sinon `flushCreateDraft` + `CloseDraftConfirm` (SP voisin, `role=alertdialog`, z 120, radius 22) : titre « Fermer sans publier ? », texte « Ton brouillon de <type> est conservé sur cet appareil. Tu pourras reprendre où tu t’es arrêté. », boutons `Continuer l’édition` (focus auto) et `Fermer` (danger) ; Échap = continuer l’édition. Aucun focus trap dans l'alertdialog.
- Hauteur : CF:2191-2196 (`80dvh` en height/min/max !important) puis CDL:8-11 (`min(541px, 100dvh-32px)`, spécificité (0,3,0)). Le `min-height:80dvh` d'origine subsiste et l'emporte sur le max-height : hauteur effective probable 80dvh (≈675 px sur 844), pas 541 (à vérifier). Corps `overflow:hidden`, formulaire scrollable seul, footer collé (CDL:13-29).
### B.2 Moteur, brouillon, validation (communs à Post, Story, Sortie, Kit, Club)
- `CreateFormEngine` (ENG:84-223) : react-hook-form + zodResolver(SCH), mode `onTouched`, revalidation `onChange`, `<form noValidate>`. Soumission : `handleSubmit` ; échec de validation → focus du 1er champ fautif en changeant d'abord d'étape (stepErrors.ts) ; erreur serveur → `root.server` + `<p.lkdv-create-engine-error role=alert>` (ENG:216-220) ET `.lkdv-form-error role=alert` en tête (CFD:65, via `onError`) = même message annoncé deux fois. `submitError` n'est remis à zéro qu'au début des submits de Story/Sortie/Club/Kit (pas Post).
- Résumé d'erreurs `FormErrorSummary` (titre « Corrige ces points avant de continuer. », une ligne-bouton par erreur, libellés `CREATE_FIELD_LABELS`) + `InlineError` sous chaque champ (`role=alert`, 10 px/600 #7a241c). Messages en français (SCH).
- Brouillon (`useCreateDraft.ts`) : clé `lkdv.create-draft:<kind>:v1` dans localStorage, écriture débattue 400 ms, flush à la fermeture/démontage, effacé après succès ; les `File`, médias locaux non envoyés et `blob:` sont écartés (seuls les médias déjà `uploaded` avec URL survivent). Aucun indicateur « brouillon restauré » (`draftRestored` jamais lu hors moteur), pas de flush sur `pagehide/visibilitychange`.
- Médias (`MediaPicker`, upload.ts) : accept `image/*,video/mp4,video/quicktime,video/webm`, max 10 (post) / 1 (story, couvertures), 50 Mo par fichier, upload IMMÉDIAT à la sélection avec progression 10→100 %, réessai, statut « Prêt / Envoi n % / Envoyé / Échec de l’envoi », texte alternatif par média (≤200, placeholder « Décris cette image… », libellé « Texte de l’image »), réordonnancement par boutons Monter/Descendre et drag HTML5 (inutilisable au doigt), suppression par double-clic ou corbeille, 1er média = couverture (badge « Couverture »), pas de recadrage ni de rognage. Images : métadonnées EXIF retirées (`stripImageMetadata`) ; vidéos non transcodées. Bucket `carnet-media` (public) pour posts/sorties/clubs/kits ; `stories-private` (URL signée 24 h) pour les stories. Messages : « Tu peux ajouter 10 médias maximum. », « Format non accepté : <nom>. », « <nom> dépasse 50 Mo. ». Zone de dépôt (`.lkdv-media-dropzone`) masquée par `display:none` (CF:~2252-2262) : l'ajout se fait via l'aperçu `FormPreview` (role=button, clic ouvre le 1er `input[type=file]`).
- Aides : `Field`(form-fields.tsx:6-23) rend `<label>` + `hint`, mais CF:2249-2282 passe TOUS les labels, hints, notes, `legend` de dates et `.lkdv-form-label` en `display:none`/clip (« Aucun libellé/hint/note visible : placeholders uniquement ») ; un bloc intermédiaire (CF:1850-1876) les rendait visibles mais est écrasé plus bas. Conséquence : l'étiquette n'existe que pour les lecteurs d'écran ; les champs sans placeholder (date, datetime-local, selects, stepper) n'ont AUCUN libellé visible.
- Éléments décoratifs au-dessus du pager : `FormPreview` (aperçu réel type+titre+résumé+vignette) et `CreationSignature` (carte « postale/viseur/ruban/blason » selon le type) ; les cartes d'info `InfoCards` (CaptionRuler, PollBalance, DifficultyLadder, CapacityGauge, SafetyManifest, MeetingPin, StoryLayerStack, StoryTrim, JoinStepper, KitRing, KitPackingMatrix).
- Clavier mobile : aucune gestion explicite (pas de `visualViewport`, `interactive-widget`, ni `scrollIntoView` hors carte carnet) ; tiroir ancré `bottom:0` en `dvh`, donc champs bas et footer collé peuvent passer sous le clavier iOS.

## D. Problèmes d'UX et d'accessibilité
### D.1 Cibles < 44 px
- A : boutons Rejoindre/Quitter 30 px (CF:2047) ; mini-capsule 25 px (CF:1088) ; Effacer la recherche 26 px (CF:955) ; compteurs j'aime/commentaires 32 px (carnet-tile.css:78) ; Effacer (état vide) 32 px ; CTA 38 px ; poignée 18 px de haut.
- B : pastille de capsule d'étapes 25 px (CF:1838) ; `lkdv-create-step-back` 26 px (CS:519) utilisé pour `+`/`×` des options de sondage et questions ; boutons × des chips 18×18 ; stepper 38 px ; actions média 30×30 (CF:2207) ; légende média 32 px ; bouton ✓ carnet 44×30 ; barre des jours 38 px ; `lkdv-ai-improve-auto` 28 px ; sélecteur de type 44 px OK.
### D.2 Tailles de texte et zoom iOS
- Champs < 16 px (zoom automatique iOS au focus) : recherche 13/13.5 px ; tous les `.lkdv-form-field` 13 px ; stepper 13 px ; légende média 11 px ; seuls les champs de la carte Carnet sont à 16 px (CMC:137).
- Textes ≤ 9 px : type de résultat 8.5 px (CF:970), légende « Texte de l’image » 8 px (CF:2214), format post `small` 8.5 px (CF:2108), compteur `lkdv-tag-chip span` 9.5 px, dates du formulaire Carnet orphelin 9-10 px (CF:~2285-2297), note de progression 6 px (CF:2128).
### D.3 Libellés, focus, contrastes
- Libellés invisibles (B4) : champs date, datetime-local, selects, steppers sans aucun texte visible une fois la saisie commencée ; placeholders disparaissent à la frappe. Sélecteurs « Audience », « Niveau », « Saison » sans étiquette visible.
- Contrastes : inactif de la capsule de création rgba(23,64,44,.55) sur verre clair (contraste estimé ≈3:1, non mesuré) ; mini-capsule icônes #56665D 15 px ; teintes de type (#8A6A2F/#A05A3C/#4B6B7C ≈5-6:1 sur blanc pur, calcul manuel) mais en 8.5 px.
- Focus : l'alertdialog de confirmation n'a pas de piège de Tab ; le focus visible n'est défini que pour la capsule (LC:86) et les boutons de confirmation ; champs `outline:none` avec bordure #17402c seule (CF:924-926) ; flèches ←/→ du StepPager interceptées même dans un `<input>` (SP:145-148) → changent d'étape au lieu de déplacer le curseur.
- Poignée `aria-hidden` : fermeture au clavier par Échap uniquement ; pas de bouton Fermer visible dans les deux tiroirs.
### D.4 Erreurs, brouillons, pertes de saisie
- Recherche : erreurs réseau/Supabase indistinguables de « Aucun résultat » ; sections Carnets/Clubs/Sorties : erreur sans réessai, listes vides sans message ; « Créer » et « Tout voir » mènent à la page courante.
- Rejoindre/Quitter : pas d'état occupé ni de désactivation (double envoi possible) ; mise à jour `members_count` côté client en deux requêtes non atomiques ; pas de gestion d'événement complet.
- Création : l'erreur serveur est affichée deux fois ; les erreurs d'envoi de média (audience non publique) n'apparaissent qu'à la soumission ; le champ restreint la photo mais l'audience est choisie plus bas ; événement créé avant le post (incohérence si échec) ; club créé puis erreur d'adhésion sans rollback.
- Brouillons : actifs pour Publication, Story, Sortie, Kit, Club (localStorage, 400 ms) sans notice de restauration ; médias non téléversés jamais restaurés ; AUCUN brouillon pour Carnet (CarnetMapDrawer) : fermeture, glisser la poignée (>80 px) ou clic sur le voile détruit tracé, jours, moments, photos sans confirmation ; photos de moments jamais envoyées ; couverture vide.
- Clic accidentel sur le voile ou glissement de 80 px ferme le tiroir ; le glisser sur la poignée n'est pas annulable ; le swipe horizontal en Sections peut se déclencher en sélectionnant du texte ou en balayant une carte.
- Réorganisation des médias par drag HTML5 et suppression par double-clic : inopérants au toucher (seuls Monter/Descendre/corbeille de 30 px).
