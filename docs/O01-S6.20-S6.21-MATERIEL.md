## Ce qui est livré

### S6.20 — réglages de notifications sportives

- La carte « Notifications » du drawer Compte ouvre un sous-drawer
  (`NotificationPreferencesSheet`) au lieu d'afficher seulement quatre pilules.
- Le sous-drawer réutilise `OverlaySheet` (le composant de sous-drawer du dépôt) :
  focus piégé, `Escape`, clic sur le scrim, retour du focus au déclencheur, corps
  du drawer parent non démonté.
- Les quatre catégories historiques (`social`, `loans`, `orders`, `system`) restent
  disponibles et sont écrites dans `user_profiles.notification_prefs`.
- Des contrôles fins par type et par canal (`application`, `email`, `push`) sont
  ajoutés pour les types réellement émis :
  - social : publications, carnets, mentions, abonnements, republication,
    invitations de voyage ;
  - clubs et équipages : invitations, demandes, tâches, dépenses ;
  - défis : fin de défi ;
  - matériel : demande de prêt, prêt en retard ;
  - commandes : confirmation, expédition, livraison, annulation ;
  - système : trophée, signalement pris en compte.
- Les emails déjà regroupés dans le digest par `notify()` (`post_liked`,
  `carnet_liked`, `new_follower`) sont affichés désactivés, avec l'explication
  « regroupé dans le digest » : aucun réglage qui serait ignoré n'est proposé.
- Les types dont le producteur n'enfile aujourd'hui aucune livraison email/push
  (`notify_activity` ou insert serveur : commandes, prêts, défis, trophées,
  demandes d'équipage, mentions) n'exposent que le canal « App » ; les canaux
  email/push sont désactivés au lieu de promettre un envoi inexistant.
- `sos_alert` n'est pas exposé : `notify()` le force à tous les canaux.

### S6.21 — langue et unités

- La carte « Langue et unités » ouvre un sous-drawer (`LanguageUnitsSheet`) qui
  réutilise le même `OverlaySheet`.
- Langue : seules les langues réellement activées par les drapeaux
  `NEXT_PUBLIC_I18N_*_ENABLED` sont proposées. Le français reste la langue source.
  Le choix passe par `LocaleProvider.setLocale` (cookie `lkdv_locale`) et est
  mémorisé dans `user_account_settings_v1.language`.
- Unités : `Automatique`, `Métrique`, `Impérial`. Le choix écrit
  `user_account_settings_v1.unitSystem`, le cookie miroir `lkdv_units` et émet
  `lkdv:unit-setting`.
- L'aperçu couvre distance, allure, altitude et poids via `formatDistanceIn`,
  `formatPaceIn`, `formatElevationIn`, `formatWeightIn`.
- `useMeasurePrefs` devient le hook commun ; le Compas l'utilise et Explorer v2
  s'y abonne. Un changement d'unité s'applique sans rechargement.
- Aucune valeur métier n'est convertie en base : les distances, durées,
  altitudes et poids restent stockés en km, secondes, m et g. Seul l'affichage
  change.

Aucune migration n'est créée. `notification_preferences` existe déjà dans le
schéma de production et est lue par `notify()` et `/api/notifications/process`.
La forme supposée est celle du baseline de production :
`(user_id, notification_type, in_app_enabled, email_enabled, push_enabled)`.
Une base de développement qui aurait l'ancienne forme `(id, user_id unique,
preferences jsonb)` doit être réalignée avant la recette ; ce n'est pas une
migration de cette fiche.
Les colonnes `quiet_hours_*` et `push_preview_enabled` de la migration
`20261013240000_notification_comfort.sql` ne sont pas touchées.

## Ce qui n'est pas livré, et pourquoi

- **Sports** et **segments** : aucun producteur de notification n'existe dans les
  triggers, les inserts serveur ou les types du dépôt. Le sous-drawer l'indique
  explicitement ; il n'affiche pas de fausse case et ne crée pas de ligne.
- **Clubs** au sens `clubs` / `club_topics` : les discussions de club produisent
  seulement `mention` (type partagé avec les publications). Les notifications
  d'équipage (`group_*`) sont affichées dans « Clubs et équipages », sans les
  confondre avec la table `clubs`.
- **Types annoncés par le contrat mais sans producteur vérifié** :
  `follow_request`, `follow_accepted`, `points_earned`, `system_update`,
  `loan_returned`, `loan_accepted`. Ils ne sont pas proposés tant qu'un
  producteur réel n'existe pas.
- **Heures calmes** : la table les supporte, mais la fiche ne les demande pas ;
  aucun réglage n'est ajouté pour éviter une écriture partielle par type.
- **Autres surfaces d'unités** (cockpit randonnée `StatsSheet`, carnets, fiches
  matériel, Kit Studio) : elles gardent leurs formateurs historiques. Les
  unifier demanderait de remplacer leurs helpers par `lib/i18n/measure` et de
  traiter leurs tests de non-régression ; c'est une dépendance à planifier, pas
  un service externe à simuler.

## Dépendances

- Fiches parentes `A02` (historique/fiche) et `N01` (guidage/recalcul) : non
  nécessaires pour ce périmètre de réglages ; aucun contrat de ces chantiers n'a
  été modifié.
- `notification_preferences` : RLS propriétaire déjà en place. L'API ajoute une
  validation `zod` stricte et ne permet que les types du catalogue.
- `notify()` : lit les préférences par type ; les catégories historiques ne sont
  qu'un miroir de compatibilité.
- Langues : chaque langue autre que le français reste dépendante de son drapeau
  de build et de la couverture de traduction. Le sélecteur ne les invente pas.
- Unités : le cookie est un miroir serveur ; le localStorage est la source de
  l'interface. Les deux sont écrits ensemble.
