## 3. Livré

### 3.1 Moteur pur des marqueurs

- `map/distanceMarkers.ts` :
  - `buildDistanceMarkers(geojson, units)` dérive les positions par
    interpolation haversine sur les lignes réelles (`routeLines`) ;
  - intervalles exportés : `METRIC_MARKER_INTERVAL_M = 1 000`,
    `IMPERIAL_MARKER_INTERVAL_M = 1 609,344` ;
  - libellés localisés (`1 km`, `2 mi`) et plafond `MAX_DISTANCE_MARKERS = 400` ;
  - une `MultiLineString` est parcourue ligne par ligne : le raccord n'est pas
    compté comme de la distance, donc aucun marqueur n'est placé dans un trou ;
  - une coordonnée invalide est ignorée, jamais interpolée.

### 3.2 Carte

- `map/MapStage.tsx` :
  - nouvelle prop `distanceMarkers` ;
  - projection DOM des marqueurs dans l'overlay existant, avec la même règle que
    les repères : rien sous le tiroir (`sheetHeightPx`) ni sous le chrome ;
  - marqueurs non interactifs (`pointer-events: none`) et masqués aux lecteurs
    d'écran (information répétée, le tiroir porte le sens) ;
  - `data-distance-m` expose la distance réelle pour la recette.
- `styles/explorer-v2.css` : style `.xp-km-marker`, placé sous les épingles.

### 3.3 Menu commun et retour au parent

- `sheet/SheetContent.tsx` :
  - section **Éléments visibles** : marqueurs de distance, itinéraires, eau,
    refuges/bivouacs, sommets/belvédères, accès, dangers ; les marqueurs sont
    actifs par défaut dès qu'un itinéraire prêt existe, et masquables ;
  - chaque ligne n'est active que si des données existent dans la zone ; les
    comptes affichés sont ceux de `place.pois` ;
  - la neige est explicitement indisponible ;
  - une entrée **Éléments visibles** est ajoutée à l'onglet Trace de
    l'itinéraire : elle ouvre le même menu, donc le même composant de drawer.
- `state/store.ts` et `state/types.ts` :
  - `sheetParent` mémorise le tiroir, sa hauteur et son onglet ;
  - `openLayers()` ouvre le menu commun, `closeLayers()` restaure le parent ;
  - le bouton Calques du chrome passe par `openLayers()`.
- `ExplorerV2.tsx` :
  - calcule les marqueurs une fois depuis `slopeRoute` (itinéraire armé ou figé
    de la séance) et l'unité du pays ;
  - filtre les épingles selon `layerVisibility` : les anciens interrupteurs
    « eau / refuges / dangers » agissent enfin sur la carte, sans filtre
    fictif ;
  - le repère ouvert reste visible même si sa famille est masquée.

## 4. Limites assumées

1. **Géométrie obligatoire.** Sans itinéraire prêt (`status === 'ready'`), aucun
   marqueur n'est construit ; le tiroir invite à choisir un itinéraire, ou
   annonce le chargement / l'indisponibilité de la géométrie. Une route de
   démonstration `unavailable` ne produit rien.
2. **Pas de marqueur sous 1 km / 1 mi.** Le contrat de la fiche est kilométrique
   (ou mile en unités impériales) ; aucun sous-pas n'est inventé.
3. **MultiLineString discontinu.** Les lignes sont cumulées sans compter le
   raccord ; le kilométrage affiché peut donc être légèrement inférieur à la
   longueur réelle d'un itinéraire réellement discontinu. Aucun marqueur n'est
   placé dans le vide.
4. **Plafond de 400 marqueurs et collision d'étiquettes.** Une trace très longue
   est tronquée à l'affichage pour ne pas saturer le DOM ; à l'écran, une
   étiquette trop proche d'une autre est omise (écart minimal 38 × 20 px) pour
   rester lisible. Ce sont des limites d'interface, pas des données.
5. **Marqueurs informatifs.** Ils ne sont ni cliquables ni annoncés un par un aux
   lecteurs d'écran ; le menu donne le nombre et l'intervalle.
6. **Visibilité liée aux sentiers.** Masquer « Itinéraires et sentiers » masque
   aussi les marqueurs : aucun libellé ne flotte sur une carte sans tracé.
7. **Écart avec `distance_km`.** La métadonnée serveur et la somme des segments
   peuvent différer ; le marqueur suit la géométrie réellement dessinée.
8. **Neige / avalanche.** Aucune source n'est branchée ; la ligne est désactivée
   (blocage 14 de `BLOCAGES.md`).
9. **Source et date.** Les tracés et repères viennent de la géométrie
   OpenStreetMap déjà exposée par l'Explorer (© OpenStreetMap contributors,
   ODbL). Le schéma ne porte pas de date de levé par repère : elle n'est pas
   affichée plutôt que fabriquée. La pente garde sa source DEM existante
   (K3.04).
10. **Pas de persistance.** Aucun nouveau champ, aucune migration, aucun réglage
    serveur : `layerVisibility.distanceMarkers` vit dans l'état de session, comme
    les autres calques.
11. **Tests reportés.** Aucun `tsc`, lint, build, test unitaire, E2E ou capture
    n'a été exécuté dans cette tranche.
