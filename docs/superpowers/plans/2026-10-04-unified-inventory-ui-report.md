# Unified inventory UI report

Implemented mode-first common creation/editing form and selected-item detail directly in the inventory page. Retained existing scan/comparator tools. Uses local Apple UI Designer and Aura Interaction Design guidance: quiet system hierarchy, existing forest/sage tokens, 44px form/table actions, keyboard-native table buttons and existing keyboard-accessible card primitive, focus and scroll continuity, reduced-motion-compatible shared buttons. No modal editor/detail remains. The OCR floating button hides during form/detail viewing to avoid obscuring mobile fields; sparse virtual grids shrink to their row count.

- Private metadata: serial, description, location, physical condition, quantity. Serialized quantity pins to one. Mode-specific initial statuses exclude active/sold states. Rental tariff is explicitly euros/day; sale price and deposit use euros converted once to integer cents.
- Generic editing omits protected `status` and `is_lent`, keeps the catalog relation, and preserves historical fields outside the form. Mode changes for available rentals/loans require returning to stock first. Active rentals/loans and sold objects have no edit/delete affordance.
- Explicit lifecycle endpoint sends expected current status. Sold is a two-step inline confirmation explaining manual tracking, no payment, entire record quantity and terminal archive. Return/start/availability/purchase-receipt actions use shared domain transitions. Network failures preserve form/detail and surface accessible errors; loading disables duplicate actions.
- Category, status, mode and location filters compose with search across name, brand, category, serial, description and location. Cards/table show status independent from physical condition. Archived sold and wishlist remain visible/filterable.
- Server-only catalog loader accepts UUIDs, selects only named public fields from active catalog rows, normalizes known seed category names to allowed inventory enum (unknown to Autre), validates weight/price bounds and maps public slugs. Catalog-prefilled creation opens on incoming product IDs without reopening after same-ID refresh. Inventory links back to verified server-loaded catalog slugs.
- Hub ownership KPIs, investment and weight exclude sold/wishlist; weight and total investment account for quantity. Availability counts owned records and actual inventory status, so active rentals/loans are unavailable independently from historical loan-row count.

## Validation

TDD: four interaction tests failed against the original modal/workspace implementation before changes (missing mode, catalog preservation, sale confirmation and private search/status filters). Final targeted suite: 14 passing tests across `inventory-ui.spec.tsx` (9), `inventory-catalog.spec.ts` (3), `inventory-hub.spec.tsx` (2). Coverage includes actual cents payloads, protected-field omission, expected-status sale/return requests, sale confirmation/terminal affordances, failed save/conflict persistence, combined filters, native table action, serialized quantity, catalog prefill and new-ID refresh, incompatible mode guard, public loader boundary/category mapping, and KPI/availability exclusions.

`npm run type-check` passed before final build, and root reports production-build compilation/lint/type stages passing. A concurrent repeated default-heap type-check exhausted the Node 2GB heap; `NODE_OPTIONS=--max-old-space-size=6144 npm run type-check` retry passed (root owns final aggregate verification). Targeted ESLint passed. Root agent owns final browser fixture review and production build; real Chromium review identified ambiguous implicit select naming, repaired with explicit accessible labels. No production writes, migrations, commits or deployment performed by this UI task.

## Limits

Root styled Chromium fixture review reports no page errors or horizontal overflow; final full build results are recorded by root separately. Catalog lookup gracefully returns no prefill/link on unavailable/deactivated product or lookup failure. No GTIN/GS1 verification, published listing, marketplace payment, escrow, insurance, KYC or new provider integration is claimed. Management prices and lifecycle remain private/manual. Existing unrelated full-suite baseline failures were left untouched.
